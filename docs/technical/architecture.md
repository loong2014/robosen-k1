# 首版技术方案

版本：0.2 ｜ 状态：accepted ｜ 日期：2026-10-08

输入：PRD-001 v1.1、[CR-003](../../prd/changes/CR-003-首版实施启动方案.md) 和 [CR-004](../../prd/changes/CR-004-Unity式积木画布交互.md)。关键选型见 [ADR-001](decisions/ADR-001-首版技术基线.md)。下文为新应用设计，不声称等同于原 APK 的源码结构。

## 1. 工程与技术组成

单个 Flutter 应用放在 `apps/kone_app/`，Android/iOS 共用业务代码；BLE 平台差异封装在传输层。先使用 SDK 的 ChangeNotifier/Listenable 和构造函数注入，不引入额外状态管理、DI、数据库、Unity 或 WebView 编辑器。

主要第三方能力是 BLE、权限和应用数据目录，候选版本及来源见 [依赖清单](dependencies.md)。积木画布采用 Flutter 拖放/选中/连接交互，显式节点关系决定执行顺序，屏幕坐标只决定显示。CR-004 批准用自由画布替代纵向卡片树：视口平移/缩放、积木位置和连接关系分开维护，积木移动本身不改动作计划；连接操作必须更新显式有序子节点。仍不引入 Unity 或 WebView。原应用手势阈值和视觉细节待录屏对照。

```text
apps/kone_app/lib/
  app/                      应用组装、导航、主题
  features/connection/      扫描列表、连接状态
  features/control/         实时控制界面
  features/projects/        工程列表和保存管理
  features/programming/     积木画布与参数编辑
  robot/transport/          BLE 平台适配
  robot/protocol/           纯 Dart 帧编解码
  robot/session/            会话状态、队列与业务事件
  robot/actions/            动作上传和播放控制
  programming/              工程模型、校验、编译
  storage/                  版本化文件仓库
```

测试代码中的模拟 transport 不在正式运行中冒充机器人。所有“运行成功”状态必须来自匹配的业务证据。

## 2. 模块契约

| 模块 | 输入与输出 | 错误与边界 |
|---|---|---|
| RobotTransport | 扫描设备、连接、通知字节流、写入字节、断开事件、实际写入上限 | 不解析业务命令；平台权限和服务错误明确上报 |
| K1Codec | 命令/载荷与字节流之间转换 | 拒绝超长/无效命令，跨通知缓存、错误重同步，断线清理 |
| RobotSession | 传输连接转换为业务 ready；派发状态/ACK；串行执行事务 | 区分 GATT connected、订阅建立和握手完成；会话代次隔离旧回调 |
| ControlController | 用户当前方向意图和释放事件 | 只在 ready 且非程序执行时发送，停止时丢弃待发送方向 |
| ProjectRepository | 保存/读取指定版本的工程 | 写入失败不覆盖最后有效文件；未知版本明确拒绝，不静默删字段 |
| ProgramValidator / Compiler | 有序积木树 → 不可变动作计划 → 机器人动作字节 | UI 与原始协议分离；未知节点/未验证动作编码显式报错 |
| ActionUploader / Player | 文件、机器人路径、取消；上传/播放状态 | ACK 匹配与超时独立于 GATT 完成；取消上传不误报机器人已停止 |

## 3. BLE 与控制

设备候选按 `K1-`、`K1AI-` 匹配；不假设广播一定包含服务 UUID。连接后核查 FFE0/FFE1 及实际特征属性。仅连接用户选定的一台设备。

```text
idle → scanning → connecting → discovering → subscribing → handshaking → ready
                                                ↘ failed / disconnected
```

Android 请求的 MTU 只是目标值；所有分片使用实际协商/可写上限。iOS 按平台行为取得上限，不照搬 Android 的 MTU 强制协商。候选 BLE 库提供扫描、连接、通知和 MTU API，但不同平台的行为仍需适配与实测。[库文档](https://pub.dev/packages/flutter_reactive_ble/versions/5.6.0)

订阅建立必须先于业务请求；若插件没有明确的订阅完成事件，应结合其实现和握手返回验证就绪，不用固定睡眠当作完成证明。握手回调已核对为匹配 0x0B 后设连接标记，详见协议取证增补；收到任意通知不能进入 ready。

帧格式、FF 透传特殊项、最大载荷、状态字段以 [协议报告](../../analysis/reports/蓝牙协议分析.md) 和 [Python 参考](../../analysis/reference/kone_protocol.py) 为准。首版业务不开放任意原始命令输入。

实时控制使用最新意图，避免方向命令积压；释放、指针取消、离开控制页或切后台时停止方向发送，在链路仍可用时尝试发送已验证停止指令。断线后清队列，重连不恢复运动。原 APK 的停止重发行为保留为初始对照依据，发送节奏由 T04 实机记录校准。

## 4. 上传、播放与不确定应答

文件业务块上限为 65 字节，再由传输层按实际 MTU 拆分。`0xDC` 创建、`0xE3` 写块须各自等待业务 ACK，只有上传确认完成才能请求播放。

旧协议没有可依赖的线上事务 ID，不能仅靠本地序号证明某个迟到 ACK 属于当前写块。一次仅保留一个相关事务；同码 ACK 超时或断线时取消本轮上传并标记结果不确定，在去重/恢复语义未验证前不盲重发同一块、不继续推进下一块。

不确定事务尚未结束时，同一链路禁止启动新上传来“试试看”。重连也不自动证明机器人已丢弃旧事务；恢复边界由 T06 取证后明确，无法确认时保持上传受阻，不用本地计数器伪造应答关联。

路径、ACK 成功值、`.sh` 布局、`0x17` 请求/完成条件进入 T06 的正式证据清单。内部文件名优先采用经设备验证的 ASCII 标识，中文工程名称保存在本地；若确需非 ASCII 机器人路径，再按已确认 GB18030 规则选择编码库。

程序运行与手动控制互斥；运行中止必须有独立验证依据。断线后播放结果标记未知，不擅自声称执行完成或停止。

## 5. 自有工程和编译

使用 UTF-8 JSON，CR-004 后的结构如下；这是新应用自有 schema，不是机器人动作文件。v1 按 `data-model.md` 迁移：

```text
Project {
  schemaVersion: 2, id, name, targetModel, viewport,
  rootId, nodes: [{ id, type, orderedChildIds, params, position }]
}
```

一个起始根节点，显式有序子节点，避免父节点和子节点双写形成两个权威来源。循环包含子序列，动作含关节目标及速度/延时参数；参数单位和范围以原 APK 编译与实机证据确定，未确认前不将 raw 值标为“度”或“毫秒”。

编辑时校验唯一 ID、根节点、引用、非法图环（区别于有界循环积木）及参数，允许画布上暂时未连接的积木；运行前还要检查所有节点从起始积木可达，以及展开预算。超过设备/资源预算时报错，不截断程序。设备预算由 T06 校准。

持久化用应用数据目录中的版本化文件，写临时文件、校验并替换，保留最后有效版本；具体恢复流程通过故障注入验证。显示坐标与执行语义均保存。未知 schema 不覆盖原文件。

编译分两步：图 → 标准化动作计划；动作计划 → 经验证的 `.sh` 编码。第二步证据未齐时只能报告尚不支持机器人执行，不能输出任意字节当作有效动作文件。

## 6. 权限、日志和测试

仅按平台请求当前 BLE 功能所需权限。权限拒绝、蓝牙关闭和连接失败都允许用户恢复；运行权限由 permission_handler 与 BLE 状态共同处理。[权限库文档](https://pub.dev/packages/permission_handler/versions/13.0.2)

诊断日志记录时间、会话、方向、原始字节、解析结果和状态；默认本地保存并限制体积。日志在用户导出前不上传；序列号/地址等只在定位问题需要时记录，分享前脱敏。

测试使用原生向量、模拟传输、编辑器 widget、文件恢复、真机 BLE 与机器人动作五类证据。详细用例见 [测试草案](../testing/acceptance-cases.md)。
