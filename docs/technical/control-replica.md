# 蓝牙控制与动作中心技术方案

版本：0.2｜状态：accepted｜2026-10-08｜关联 CR-005 v0.2、REQ-CTL-001～005、REQ-ACT-001/002、REQ-BLE-001、REQ-UX-001。

2026-10-09 用户批准 CR-005 v0.2 和关联设计；沿用 architecture.md 的 BLE / 协议 / 会话 / 控制 / UI 分层。

- `ControlController` 接收归一化两轴与八方向意图，复用串行会话和过期意图检查。释放 / 取消统一回中；停止过程与新运动采用代次隔离。新增播放占用与程序占用不能只是页面禁用，发送前仍检查。
- 动作中心和快捷键共用动作播放服务，只接受当前设备的合法完整路径，通过编码接口生成 GB18030，发送 0x17。播放状态区分准备、请求发送、等待回传、播放进度、停止请求、失败 / 未知；不以写入完成作为执行成功。完成通知没有线上动作 ID，需单次占用与会话隔离，旧请求未清楚结束时不直接开始新动作。正常进度限定 0～100，100 表示收到原版动作中心的完成条件；异常值不解锁。该选择保留了原版动作中心的等于 100 条件，控制页另一回调 ≥100 的差异另记，仍待实机核对。
- `RobotActionEntry` 包含目录、原名称、完整路径和来源；目录 + 名称作为条目身份，不能仅按名称去重。目录回传的原始字节保留到诊断 / 对照证据；中文不得改拼音、去空格或 Unicode 规范化，不擅自去扩展名。非法路径、解码失败、同一身份的异常回传需可报告，不能为了列表看起来完整而静默丢弃。
- 动作目录服务按原表顺序读取 `Action/`、`Action/skill/`、`DownloadAction/` 的全部条目；0x16 是名称回传、RX 0xFA 是目录结束。全目录成功结束才标 complete；每目录记录 loading / complete / failed / cancelled，部分结果可展示并明确未读完整，不能伪装空目录。安全资源上限触发后报告不完整，而非截断后显示成功。
- 三目录表的生产和消费已在 ARM64 恢复。2026-10-09 用户提供新版 4.77 APK，SDK 映射与机器码确认查询前调用 String.TrimEnd('/')；生产请求使用 `Action`、`Action/skill`、`DownloadAction`，显示 / 播放路径保持原目录前缀。新旧版本证据分别保存，详见动作中心报告第 8 节和 directory-vectors.json。静态请求依据已经具备，真实目录集合仍待实机验收。
- RX 0xFA 在发送方向另用于关机，本目录服务只能等待其回传。当前 `RobotSession.request` 只等待同码单次响应，拟扩展会话内部事务协调：状态请求与目录多响应事务共享占用；在发送前注册监听，收集多个 0x16 后以 0xFA 结束。UI 和目录服务不能私自绕过协调直接发送。
- 超时 / 取消后的旧通知没有目录 ID。仅设置本地代次不能区分同一 BLE 会话内的迟到回传。必须确认旧事务已结束或重新建立会话后才能开始下一次读取，不自动重试并错误挂到新目录；若没有可验证的隔离方式，保持未完成状态并提示重新连接。断线后丢弃旧目录结果，设备切换后重新读取，不把缓存当当前完整目录。
- 播放、方向、目录刷新和编程启动统一检查占用。刷新只在执行空闲时启动；正在读目录时不开始播放。停止意图仍需能取消排队的运动，事务等待不应阻塞必要停止发送。返回 / 切页 / 后台走统一退出保护，停止已发送与物理已停止分开表达。
- GB18030 编解码优先使用最小 MethodChannel 桥接 Android / iOS 系统能力；测试使用可注入的编码接口，真实平台分别核对可信中文向量。编码失败明确返回，不回退 UTF-8 发给机器人。
- 三项绑定使用独立 `control-shortcuts.json`，schemaVersion=1；不改工程 v2，也不要求原 APK JSON 兼容。读写串行、临时文件校验后原子替换；未知版本 / 损坏文件保留并提示，不悄悄重置。更换设备 / 刷新目录后核对已绑定条目，不可用绑定显示原名与不可用状态，不自动改绑其他同名动作。默认 ProAction/ 三项是原快捷配置独立来源，不计入目录全量覆盖，也不改写成 Action/。
- 音量控制独立处理 500ms 合并发送、回传同步和会话代次；范围按本提案 0～100，不把它标为静态已恢复的原版量程。电量区分缺字段与有效原始值，展示含义待标定。
- UI 复用 Flutter SDK：八方向摇杆、三个动作快捷键、状态区、控制设置，以及从控制页进入的动作中心。动作中心支持全部 / 机器人动作 / 技巧 / 已下载分类、真实计数、刷新、长名单滚动、选择播放、进度和停止；绑定模式选择条目后返回快捷设置，不触发播放。竖屏 / 横屏自适应，不新增图像 / 视频依赖。
- 名称过滤变为 K1 / k1 前缀；BLE 发现与业务握手验证不放宽。接收状态、快捷播放进度和动作目录各有明确解析入口，页面不组原始字节。

证据入口：[静态界面报告](../../analysis/reports/蓝牙控制界面分析.md)、[动作中心报告](../../analysis/reports/动作中心分析.md)、[协议增补](protocol-evidence-update.md)。查询 SDK 已补齐，精选两张图片已提取；完整原资源布局、固定更新时间步、云端名单及真实设备名单仍未恢复，实机完成 / 中止待核实。

本方案不新增云端客户端、原 APK 本地工程导入、手掰编辑、动作文件修改 / 上传或删除。原有积木编程继续按批准的设计实施。完整目录展示与逐项播放验收分别记录，不能拿服务模拟成功代替“原版所有动作已复刻”。

## 实施细化（2026-10-09，同一批准范围）

实际条目模型为 `RobotAction(directory, name)`。`ActionCatalog` 依次协调三目录事务；`ActionPlayer` 与方向控制、目录共享会话操作所有权。当前编程执行仍受原 T07 格式证据门槛阻塞，未来启动必须取得同一所有权。发送队列在开始一个帧之前核对意图；帧已经分片写入后先完成剩余分片，再发送停止，避免截断载荷破坏停止帧。断线仍会立即使整代队列失效。

通知缺少动作 ID：后续动作必须先收到本轮非终态进度，才能把 100 作为完成；单独迟到的 100 不解锁。超时保持未知 / 占用，停止发送不解除为物理完成。无编号的其他迟到进度无法在纯软件中完全鉴别，不能声称此保护证明所有通知归属。

摇杆占有自身区域的触摸，页面滚动从外围开始；单指拖动、中心区、松手 / 取消保持原语义。动作页头部在横屏 / 长错误文本下可以滚动，播放中的停止按钮也位于固定导航栏。停止间隔 Timer 可随控制器退出取消。

系统桥接采用 [Flutter 平台通道](https://docs.flutter.dev/platform-integration/platform-channels?tab=android-channel-java-tab)、Android [CharsetEncoder](https://developer.android.com/reference/java/nio/charset/CharsetEncoder) 严格错误处理、iOS [GB_18030_2000](https://developer.apple.com/documentation/corefoundation/cfstringencodings/gb_18030_2000?language=objc) 转 NSStringEncoding。无 UTF-8 回退，无新增产品依赖。编码向量来自 CPython gb18030，iOS 模拟器已跑实际 MethodChannel；Android 原生执行待设备。资源仅两张 PNG，来源 / 哈希见 assets/control/README.md，不引入 Unity。
