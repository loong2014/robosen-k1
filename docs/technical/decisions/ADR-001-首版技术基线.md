# ADR-001：首版 Flutter 技术基线

版本：0.1 ｜ 状态：accepted ｜ 日期：2026-10-07

关联：PRD-001 v1.0、CR-003、T01～T08。

## 背景与约束

双平台应用需要原始 BLE 字节收发、积木编辑和本地工程保存，执行方式为上传文件后播放。仓库已有离线协议参考，本机已有 Flutter 3.44.0 / Dart 3.12.0。第一轮目标是可验证的控制与程序执行闭环。

## 建议选择

- 复用本机 Flutter 3.44.0 / Dart 3.12.0，创建单应用工程，保留版本固定信息。
- UI、状态通知、注入和导航优先用 SDK 能力。积木使用 Flutter 原生组件，不引入 Unity 运行时或 WebView/JavaScript 桥。
- BLE 候选固定为 flutter_reactive_ble 5.6.0；权限为 permission_handler 13.0.2；目录为 path_provider 2.1.6。版本存在与能力已查官方发布页，工程兼容尚未构建验证，详见依赖清单。
- 应用声明的最低系统提案为 Android API 24、iOS 15。编译 SDK/Gradle/AGP/Kotlin 先以固定 Flutter SDK 的模板为依据，在首次可复现构建时记录具体值，不能将其混同于产品最低系统。
- 自有工程用版本化 JSON，机器人动作编码独立。暂不引入数据库、云端和原工程格式导入器。

## 比较与代价

自建原生 BLE 插件会增加 Android/iOS 两套维护；候选库已有所需基本 API，先用薄适配层集成。若 T03 发现订阅/写入行为不能满足协议，应提出具体证据再调整选型。

嵌入 Unity 或 WebView 积木编辑器能复用另一套渲染能力，但会引入桥接、资源和双生命周期。当前范围采用原生 Flutter 更便于与项目模型、测试统一；完整 3D 效果不在本次提案范围。

文件存储适合当前本地工程集合；未来有复杂查询和大规模资源管理时再评估数据库，不提前建立同步体系。

## 验证与决定

T01 验证依赖解析和双平台构建；T03 验证 BLE 权限、订阅、无响应写入和断线；T05 验证工程保存恢复。版本兼容或平台下限不满足时保留失败证据，不能静默替换关键库。
