# 首版实施启动方案

版本：0.2 ｜ 状态：approved ｜ 日期：2026-10-08

关联：PRD-001 v1.1、[CR-003](../../prd/changes/CR-003-首版实施启动方案.md)、[CR-004](../../prd/changes/CR-004-Unity式积木画布交互.md)、[技术方案](../technical/architecture.md)、[验收用例](../testing/acceptance-cases.md)。当前已开始实施，进度见 [实施记录](implementation-status.md)。

## 1. 开工结论

现有资料足以支持分阶段实施：先建 Flutter 工程、离线协议、BLE 会话与基本控制，再完成积木编辑、保存和动作执行。动作文件格式与播放命令的取证应从第一阶段开始，不延后到编辑器完成之后。

| 工作 | 现有依据 | 结论 |
|---|---|---|
| 协议编解码 | Python 参考、96 组原生编码器对照、31 种通知切片 | 足以实现和离线测试 |
| BLE 扫描连接 | 设备名前缀、FFE0/FFE1、订阅/握手时序 | 足以实现适配层；业务 ready 需实机验证 |
| 实时控制 | 四个方向和停止的原生调用路径 | 足以实现指令层和页面；实际方向效果、发送节奏需实机确认 |
| 积木编辑与保存 | 起始、动作、关节目标、循环的数据结构 | 足以实现自有工程和编辑器；无需原 APK 工程格式兼容 |
| 编译与上传执行 | 编译入口、创建文件、分块 ACK、播放路径 | 可以开展取证和模块开发；完整 `.sh` 编码与播放结果仍是实机闭环前置条件 |

## 2. 已批准首版交付范围

保留已确认的双平台、双型号、K1AI 验收和手掰后续安排。以下具体化内容已随 CR-003 批准：

- 界面为设备连接、实时控制、工程列表、积木编辑四个主要页面，先用中文 Flutter 原生界面。
- 连接单台机器人；手动选择连接、断开和重连，显示权限/蓝牙关闭/连接中/握手中/就绪/错误状态。
- 控制首批提供四方向与停止，物理方向含义按原 APK 与实机结果校准。其他预置动作、变形和设置不自动纳入。
- 积木首批提供起始、动作（关节目标、速度、延时）、有限次循环；支持新增、连接/排序、编辑参数、删除、保存和重开。暂不纳入判断、舞蹈、音频、完整 3D 预览。
- 无机器人时可编辑、保存工程；连接就绪后编译、上传、执行。执行期间避免手动控制与程序命令混用。
- 工程仅使用自有版本化格式。参考 APK 的动作执行链不代表必须复制其界面、账号和文件管理体系。

## 3. 任务与依赖

所有任务已获实施授权，按各自前置条件推进；不要求全部实机验证先于任何代码，但不得跳过当前任务依赖的验证。

| 任务 | 内容与输出 | 依赖 | 完成标准 / 测试 |
|---|---|---|---|
| T01 | 在 `apps/kone_app/` 建立 Android/iOS Flutter 工程，固定 SDK/直接依赖，记录实际锁文件和原生工具版本 | CR-003/ADR-001 接受 | 格式、静态分析、基础测试、Android debug 和 iOS 无签名构建通过；TC-BUILD-01 |
| T02 | 实现纯 Dart 旧协议编码、流解析、状态解码和离线向量 | T01 | 96 组原始向量匹配，分片/错误/断线清理测试通过；TC-PROTO-01～03 |
| T03 | 实现权限、扫描、GATT、订阅、握手和串行会话；保留原始诊断日志 | T02 | 两平台连接 K1AI 到业务 ready；断线旧事务不泄漏；TC-BLE-01～04 |
| T04 | 四方向/停止控制页及生命周期处理，记录实机指令节奏 | T03、方向/停止证据 | K1AI 动作与原 APK 对照；释放和断线不再发过期方向；TC-CTL-01～02 |
| T05 | 积木工程、Unity 式自由画布、扩展积木、校验与本地保存恢复 | T01、CR-003、CR-004；原应用取证与语义缺口分项把关 | 工程重开后节点、参数、画布、连接关系、顺序一致；旧 v1 可迁移；无 BLE 也可编辑；TC-EDIT-01～04 |
| T06 | 补齐动作文件、关节参数、播放/完成/停止、文件路径和 ACK 的协议证据，产出最小动作样本 | 可从 T01 同期开始；实机部分需要原 APK/设备可用 | 形成能解释最小动作字节和行为的规格；TC-EVID-01 |
| T07 | 积木树转执行计划、`.sh` 编码、文件上传及执行状态 | T02、T05、T06 的对应证据 | 编译样本对照、ACK/断线模拟、K1AI 真实执行；TC-RUN-01～04 |
| T08 | Android/iOS 端到端回归和验收报告；单列 K1 兼容状态 | T03～T07 | 两平台在 K1AI 完成主流程；每项用例有结果和证据；TC-E2E-01 |

T05 可在连接实机等待期间推进；T06 是执行闭环的关键路径，不因 UI 进展顺利而推迟。此处“同期”指独立任务可交错推进，不额外授权创建并行 agent。

CR-004 将 T05 补充分为：T05a 原 APK 可见积木与操作取证，T05b Flutter 自由画布与触摸连接，T05c 自有工程 v1→v2 迁移、新积木离线模型与旧工程回归，T05d Android/iOS 真机操作对照。T06/T07 增补动作子积木与单条指令的执行语义证据。舞蹈/判断仅调查原应用可用性，调查不等于开放功能。

## 4. 协议取证任务 T06

先从已导出的图形化编译方法、原生调用和动作资源继续分析，再与原 APK 的最小程序进行字节/实机对照。按“一个动作 → 两个顺序动作 → 有限次循环 → 改变速度/延时”逐个改变变量。

每个样本记录：原 APK 版本、设备型号/固件、编辑内容、操作顺序、动作文件或实际发送字节、通知结果、实际运动。无法取得的部分标为未验证；不以 Python/Dart 自身 round-trip 作为固件兼容证明。

必须回答：文件头/帧布局/时间参数、关节目标编码、创建路径规则、上传 ACK 内容与超时边界、播放载荷、完成条件、文件播放中止方式。未确认 `0x0C` 能停止程序文件前，不将其当作程序急停。

若原生代码仍无法还原关键格式，需要使用用户可用的原 APK 和 K1AI 采集最小样本；这会阻塞 T07 的真实执行部分，不阻塞 T02/T05。

## 5. 就绪程度与环境

本机读取得到 Flutter 3.44.0 / Dart 3.12.0、Xcode 26.4.1、CocoaPods 1.16.2、JDK 17.0.16。版本可用不代表工程已经构建通过；Android SDK 安装情况、iOS 签名、手机连接和固件仍待 T01/T03 核查。

依赖版本提案见 [dependencies.md](../technical/dependencies.md)。先复用已有 SDK，不默认升级整机工具链。已批准支持下限为 Android API 24、iOS 15，不代表已经通过各系统测试。
