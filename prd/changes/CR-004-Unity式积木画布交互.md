# CR-004：Unity 式积木编程画布交互

类型：需求变更｜审批状态：approved｜交付状态：in_progress

提出日期：2026-10-07｜当前基线：PRD-001 v1.0、CR-003 v0.1｜提案版本：0.1

关联需求：REQ-VIS-001、REQ-UX-001、REQ-COMP-001；REQ-VIS-002 的执行链保持既有目标。

## 原始诉求与变更

用户原话：“复刻原生的Unity编程画布方案，编程是我们重要的功能，操作上要尽量复刻”。此前用户指出当前积木模块没有完整复刻。用户进一步选择“同时扩展原 APK 积木种类”。本变更同时提高画布交互保真度并扩大积木范围。

| 项目 | 已批准基线及当前实现 | 拟议行为 |
|---|---|---|
| 编辑工作区 | PRD 允许中文 Flutter 原生页面，不要求像素复刻；现为纵向卡片树和连接位置 | 用 Flutter 实现自由画布与积木形态，支持从积木区拖入、画布移动、连接预览、吸附及重新编排 |
| 积木语义 | 开始、动作、有限循环；有序树决定执行，坐标只记录显示 | 加入原 APK 可证实的动作子积木和单条指令，并调查舞蹈、判断积木；保持语义树与坐标分离，画布位置不改变执行顺序 |
| 编辑操作 | 点击选中，长按拖动已连接节点，弹窗改参数、删除 | 在画布中完成选中、拖动、连接/断开、调整顺序、参数编辑、删除、撤销/重做；触摸操作同时适配 Android/iOS |
| 工程 | 自有 JSON v1 可保存重开；原版工程互用不在首版 | 已有工程无损打开；新增画布状态须明确版本/迁移或在现有字段安全表达 |

用户选择同时扩大积木种类。推荐按下面的证据分层推进，同一变更追踪所有类别，但每类须具备相应语义及测试证据才标记完成：

| 原 APK 类型 | 可确认内容 | 本轮提议 | 待核实项 |
|---|---|---|---|
| StartBlock | 起始模型及工作区起始对象 | 保留唯一开始积木；对照原版起始模式界面 | 起始模式具体选项及效果 |
| ActionBlock | 速度、延时；UI 有设置入口 | 作为动作容器；参数用原版操作形式呈现 | 参数单位及机器人编码 |
| ActionBlockChild | 关节编号、运动值、启用、灯光字段；UI 有预制体和角度设置入口 | 作为可连接的动作子积木，保留启用与关节目标 | 值域、物理映射、灯光编码与实际可见操作 |
| LoopBlock | 循环次数与子节点 | 在画布中连接并编辑有限循环 | 原版拖动和嵌套限制 |
| SingleCommand | `RobotPose`、`LongPose` 两种枚举；UI 有创建入口，保存模型含该列表 | 加入两种指令积木的编辑/保存；执行能力以取证结果开放 | 两者用户可见名称、动作语义和编码 |
| DanceBlock | 类型、UI 预制体、`ActionKey` | 对照原应用调查可见入口与交互；若可用，补充明确的选择/保存/播放规则后实现 | 当前保存结构不含舞蹈列表，动作来源与运行语义未明 |
| IfBlock | 枚举、模型和 UI 类 | 调查是否向用户开放；如开放，另补条件类型、真假分支与保存/执行规格 | 当前工作区可见预制体字段及保存结构均未证明可用 |

上述“调查”属于本轮复刻的必要证据工作，不代表可以用空按钮或假执行冒充已实现。舞蹈和判断若确属原应用可用功能，需要把核实出的具体行为补到本 CR 并取得范围确认后实施。

## 原应用证据与缺口

- 静态证据：`analysis/cpp2il/DiffableCs/Assembly-CSharp/VisualViewBase.cs` 有按下、抬起、拖动开始/过程/结束事件；`BlockModelBase.cs` 有画布本地坐标、父 ID、子 ID。`EditorVisualInterfaceScript.cs` 有工作区初始化、拖动回调、删除及各类参数入口。这些生成的 C# 方法体为空，不能由其推断具体吸附阈值、手势、动画或视觉样式。
- 分析总结见 `analysis/reports/图形化与手掰编程复刻参考报告.md` 第 3 节。报告的“缩放、撤销重做”等属于设计建议，不是已确认的原应用操作。
- 尚缺原 APK 在手机上的画布录屏/逐步操作记录、实际积木资源图、吸附与断开行为。实现前可先按提案做可用交互，再用原应用记录校准；不能宣称像素或手势完全等同。
- 积木清单来自 `BlockType.cs`、各 `*BlockModel.cs`、`SaveVisualEditorDatas.cs` 和 `EditorVisualInterfaceScript.cs`。类型存在不代表用户可见或可执行；特别是判断和舞蹈存在上述证据缺口。

## 拟议验收标准

1. 无 BLE 时可在画布从积木区加入本 CR 已明确的积木，移动画布并在画布内拖动积木；拖动时可辨认候选连接位置，松手后连接关系和顺序可见。非法连接不丢节点或破坏原工程。
2. 连接、重排、断开/重新连接、参数编辑、删除及撤销/重做后，显示关系与 `orderedChildIds` 一致。纯粹移动显示位置不改变动作计划。
3. 保存、结束应用并重开后，节点、参数、关系、顺序和可恢复的画布布局一致；现有 v1 工程仍可打开且不丢数据。损坏/未知版本继续明确拒绝。
4. 在普通 Android 与 iPhone 触摸屏验证拖动、画布手势、连接命中区域和参数输入，记录误触及遮挡问题；与原 APK 的同任务录屏逐项比较并记录差异。没有原版记录时只标记“本应用可用”，不标“原版操作等同”。
5. 未完成 `.sh` 编码和实机执行验证前，画布仍明确标记上传执行不可用；机器人执行的既有验收不因画布改造而降级。
6. 动作子积木可设置关节目标及启用状态；单条指令的两种类型可区分、保存和重开。每一新增积木若尚无可靠执行语义，程序检查必须指出不能执行该节点，不得静默跳过。
