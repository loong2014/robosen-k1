# 测试与验收规范

本文件规定测试资料格式。[首版验收用例](acceptance-cases.md) 已随 CR-003 批准，TC-EDIT 项依 CR-004 更新；未执行用例不作为已验收证据。

CR-005 v0.2 增补已批准 [控制与完整动作中心用例](control-replica-cases.md)；执行结果见 [2026-10-09 记录](results/2026-10-09-control-replica.md)。

## 用例标准

每个测试用例包含：测试 ID、关联需求及版本、测试层级、前置条件、设备/系统/固件、输入或测试数据、操作步骤、可观察预期结果和清理方式。性能指标必须来自已批准标准，不任意填入阈值。

覆盖正常流程和适用异常场景；设备控制需要记录实际运动结果，不能只验证“发送函数被调用”。协议帧测试、模拟会话测试、手机 BLE 测试与机器人端到端验收分开记录。

## 执行证据

执行记录包含：用例 ID、应用/代码版本、执行日期、执行者、真实环境、实际结果、日志/录像等证据位置，以及 `passed`、`failed`、`blocked` 或 `not_run` 状态。不得用空白表示通过。

每份记录说明未覆盖的型号或系统。K1AI 是当前指定实机验收设备；K1 是支持目标，兼容性验证单独记录。固件版本未知时标为待采集，不能伪造。

## 验收判定

验收依据 PRD 和对应批准版本。完成动作上传与机器人正确执行分别验证；应用侧“成功”提示不能代替机器人行为证据。

现有验收目标是分别在 Android 和 iOS 上连接 K1AI 实机，完成 BLE 搜索连接、控制页实时控制、自有工程保存重开，以及编程文件上传后按其内容执行。首版不以原 APK 编辑工程导入/双向互用或手掰功能作为验收要求。具体动作集合、样例程序和指标在需求细化后写入正式用例。

测试发现行为不符合需求时登记缺陷；若建议改变需求，按 [变更流程](../../prd/WORKFLOW.md) 处理，不通过降低预期结果关闭缺陷。
