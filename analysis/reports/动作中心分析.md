# 原版动作中心：目录、列表与播放分析

日期：2026-10-08｜样本：`com.robosen.K1app` 4.75.20260601｜证据：ARM64 静态分析。

本报告服务于用户“复刻原版的动作中心的所有动作”的请求。它是取证资料，不是产品批准或机器人实测结果。地址均为样本 ELF VA。

以下第 1～7 节保留 2026-10-08 的 4.75 历史分析。2026-10-09 的新 APK、查询 SDK 签名和精选图片证据见第 8 节，不能混用两版本地址。

## 1. 核心结论

原版的机器人动作列表来自机器人回传，不是一份可以从 APK 枚举名称直接恢复的固定动作清单。已找到完整的三目录表，并追踪到连接查询、列表生成和播放调用。复刻应完整读取这三处的实际条目，逐项保留目录和名称，再调用机器人已有动作；不能把控制页的三个拳击快捷键当成全部动作。

| 机器人目录 | 动作项类型 | 证据与含义 |
|---|---|---|
| `Action/` | 1 | 机器人动作目录；具体动作名及数量由设备返回 |
| `Action/skill/` | 2 | 技巧动作目录；不能因名称与其他目录相同就合并 |
| `DownloadAction/` | 3 | 已在机器人上的下载动作；不同于手机本地下载缓存 |

这里的含义是本报告的功能说明，不是已恢复的原版中文分类文案。具体名单受实际设备及固件影响；当前没有任何机器人的目录回传或原版列表截图，不能报告确定的总数、缺失动作数或逐项实机可用性。

## 2. 完整目录表的证据链

此前控制复刻准备记录认为完整目录表缺失；本次通过 [RobotActionInterfaceScript 静态构造函数](../native/RobotActionInterfaceScript..cctor.20cf2f8.asm) 补齐：

- `0x20CF388～0x20CF3E4`：加入 `Action/`。
- `0x20CF410～0x20CF464`：加入 `Action/skill/`。
- `0x20CF490～0x20CF4F4`：加入 `DownloadAction/`。
- `0x20CF520`：将列表写入全局类型指针 `0x46130B8` 的静态字段偏移 0。
- `0x20CF538～0x20CF550`：取得 GB18030 编码器，存到同一类型静态字段偏移 8。

[K1 连接协程](../native/_CheckBleConnecting_d__29.MoveNext.20a5098.asm) 在 `0x20A5818` 读取同一全局类型指针，在 `0x20A5830～0x20A584C` 取静态列表并开始遍历。这里有实际的写入与消费关系，不是仅根据目录 getter 推断。

三个 getter 也返回对应常量：[ActionDirectory](../native/RobotActionInterfaceScript.get_ActionDirectory.20cbca4.asm)、[ActionSkillDirectory](../native/RobotActionInterfaceScript.get_ActionSkillDirectory.20cbce4.asm)、[DownloadActionDirectory](../native/RobotActionInterfaceScript.get_DownloadActionDirectory.20cbd24.asm)。

## 3. 目录查询和回传

K1 连接协程先注册动作名和目录结束事件，再遍历目录。在 `0x20A5AE0` 取得 GB18030 编码器，`0x20A5AFC～0x20A5B04` 把目录字符串与字符 `/`（0x2F）传给 SDK 函数 `0x3512C30`，编码其返回字符串，并在 `0x20A5B30～0x20A5B38` 用 `0x16` 请求。

**仍待确认：** 当前保留的方法索引只覆盖应用程序集，未恢复 `0x3512C30` 的 SDK 方法签名。调用形态提示斜线裁剪，但不能据此宣称线上载荷必然是带尾斜线或不带尾斜线的某一种。实现前需用完整元数据、该 SDK 函数机器码或原版 BLE 记录确认，不能把目录表中的字符串直接冒充已验证请求向量。

接收链路已在 [协议分析](蓝牙协议分析.md) 确认：`BTDevice.CommandInvoke` 把收到的 `0x16` 分发给动作名事件，把收到的 `0xFA` 分发给目录结束事件。**发送方向的 `0xFA` 是关机命令；读取目录不得发送它。**

[名称回调](../native/__c__DisplayClass29_0._CheckBleConnecting_g__FolderActionsNameRecive_1.20a40a4.asm) 检查当前设备和非空 payload，在 `0x20A4168～0x20A4180` 解码整个 payload；`0x20A41F0～0x20A424C` 将当前查询目录和名称组成二元条目，追加到 `AppRuntimeInfo.ActionNamesOnRobot` 对应列表。这里未见按分隔符拆成多个动作名。

结束通知没有已恢复的目录或事务 ID；重试、取消后迟到通知如何隔离仍需验证。同一会话内给请求增加本地编号，并不能让没有编号的回传自动获得可验证的归属。

## 4. 动作中心怎样显示全部条目

[首页动作中心入口](../native/MainInterfaceScript.ToRobotActionBtnClick.20c7570.asm) 检查业务连接，已连接才打开动作页面；否则进入连接流程。

[Open](../native/RobotActionInterfaceScript.Open.20c78a8.asm) 的模式 0 / 默认分支打开机器人动作，模式 1 打开手掰，模式 2 打开图形化，模式 3 隐藏手掰 / 图形化入口并保存选择回调，再打开机器人动作。模式 3 与控制页更换快捷动作的用途对应。

[ShowRobotActionBtnClick](../native/RobotActionInterfaceScript.ShowRobotActionBtnClick.20cc70c.asm) 遍历上述目录 / 名称二元列表，逐项比较完整目录字符串，分到三组。下载组还检查同名重复项。它把三组列表传给 [CreatRobotActions](../native/RobotActionInterfaceScript.CreatRobotActions.20ce97c.asm)：

| 调用位置 | 输入 | `ActionRectScript.SetValue` 类型 |
|---|---|---|
| `0x20CEBFC` | DownloadAction 名称列表 | 3 |
| `0x20CED24` | Action 名称列表 | 1 |
| `0x20CEE4C` | Action/skill 名称列表 | 2 |

创建过程循环处理各列表条目，再通过 `ShowActionsOnView` 展示。该路径没有只创建三项、只允许拳击名称或按固定预置枚举截断的证据。界面实际排版、图标和中文标签仍需 Unity 场景 / Prefab / 本地化资源或原版截图对照。

## 5. 播放、选择与停止

[ActionRectScript.MianBtnClick](../native/ActionRectScript.MianBtnClick.20df46c.asm) 按类型 1 / 2 / 3 添加对应目录前缀。快捷绑定回调分支在 `0x20DFC10～0x20DFC28` 拼接目录与名称后返回，不发送播放命令；正常播放分支在 `0x20E006C～0x20E0094` 拼接并调用静态编码器，`0x20E00E0～0x20E00F4` 发送 `0x17`。这一调用没有编程临时文件播放中的按 `.` 拆分路径步骤，不能统一套用“去掉扩展名”。同一当前动作再次点击有空载荷 `0x0C` 停止分支（`0x20E0158～0x20E0164`）。

另一套 [RobotActionViewScript](../native/RobotActionViewScript.MianBtnClick.20e3448.asm) 也将完整路径字段按 GB18030 编码并发送 `0x17`（`0x20E34F8～0x20E3560`），随后更新本地播放界面；这不证明 GATT 写入等于实际动作完成。

[SetCurrentActionPlayProgress](../native/RobotActionInterfaceScript.SetCurrentActionPlayProgress.20cc62c.asm) 把非空通知首字节交给当前动作条目。[ActionRectScript.SetProgress](../native/ActionRectScript.SetProgress.20cc4dc.asm) 显示进度 / 100，**值恰好为 100** 时恢复普通状态并清除当前动作；[ActionViewBase 的回调](../native/ActionViewBase.BTDevice_ActionProgress.20e0ae0.asm) 也以等于 100 解锁。控制页快捷按钮的另一回调使用 ≥100，两者应分别记录，不能合并成一个“原版统一完成条件”。空通知和越界值不能在新应用冒充有效完成。

原版本地更新高亮或解除占用，不等于已验证物理停止。停止、取消、断线、播放无回传及迟到回传均需新应用状态机和实机验证。

## 6. “全部动作”的其他来源边界

| 来源 | 已恢复的路径 | 当前可确认 / 未确认 |
|---|---|---|
| 三个控制快捷键 | 默认 `ProAction/打左拳` 等 | 属于快捷配置；`ProAction/` 不在上述三目录表中，不能改写成 Action/ 或冒充已查询到的目录条目 |
| 手机本地手掰工程 | 类型 4 → `BagPlayLocalActionFile.RunManual` | 是用户本地工程的编译执行流程，不能拿机器人目录名当作可导入工程 |
| 手机本地图形化工程 | 类型 5 → `BagPlayLocalActionFile.RunBlock` | 同样属于本地工程流程；现有应用的自有工程兼容目标继续有效 |
| 官方在线下载入口 | GetActionVideos / DownloadAction | 是单独联网页面；不是机器人目录查询的替代来源 |
| 手机在线缓存 | `OnLineActionDirectory` 返回本地路径 + `/OnLineAction/` | 不等于机器人上的 DownloadAction/；不能仅凭同名认为已上传可执行 |

本地工程分支的直接证据位于 `ActionRectScript.MianBtnClick` 的 `0x20DFAEC`（RunManual）和 `0x20DFD58`（RunBlock），以及 [SelectActionPlaneScript.PlayBtnOnClick](../native/SelectActionPlaneScript.PlayBtnOnClick.20d1a38.asm) 的类型 4 / 5 分支。后者不是类型 1～3 的直接播放证据。

在线入口使用 `area` 查询视频列表，响应读取 `data.video_list`；下载使用 `video_id`。URL getter 拼接服务下发的基础地址与 `Grimlock/official/AVideos` / `Grimlock/official/AVideoAction`。这些静态路由不能证明当前接口可用、内容适用于 K1/K1AI，也不能恢复完整云端名单或动作文件。本次没有访问这些服务。

证据：[GetActionVideos](../native/DownloadActionFileCanvasScript.GetActionVideos.20b8ce4.asm)、[列表回调](../native/DownloadActionFileCanvasScript._GetActionVideos_g__ActionVideoResult_13_0.20b9428.asm)、[DownloadAction](../native/DownloadActionFileCanvasScript.DownloadAction.20b912c.asm)、[视频列表路由](../native/robosen_NetUrls.get_GetActionFileVideoListURL.203b550.asm)、[动作路由](../native/robosen_NetUrls.get_GetActionFileURL.203b5e0.asm)、[手机缓存路径](../native/RobotActionInterfaceScript.get_OnLineActionDirectory.20ca98c.asm)。

## 7. 对复刻范围和验收的建议

待审 [CR-005 v0.2](../../prd/changes/CR-005-原版蓝牙控制界面复刻.md) 应覆盖三目录全量读取、分类列表、刷新、任意条目播放、进度 / 停止和三个快捷键绑定同一目录条目。完整性依据是同一机器人、同一固件、同一目录内容下的原版 / 新版路径集合对照，不能以“页面显示很多动作”验收。

目录超时或仅拿到部分结果时应明确显示未读完整；无条目但没收到结束通知不等于目录为空。跨目录同名必须保留，不能过滤成固定几个动作。模拟目录和离线编码只能验证软件，不能替代逐项原版对照和机器人执行结果。

云端新动作下载、原 APK 手机本地工程导入和手掰编辑会改变已有首版边界，需单独明确范围；它们不能被写成已复刻，也不能用虚构按钮或名单补齐。原 APK 编辑工程互用和手掰后续安排仍以已批准 PRD 为准。

本机缺原始 APK / ELF / 全量元数据和 Unity 资源；本次使用已保留的原生汇编、字符串注释、方法目录及历史报告。没有读取设备目录、发送机器人命令、修改产品代码或进行实机验收。
