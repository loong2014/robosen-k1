# CR-001：设备范围、首版方向与执行方式确认

类型：初始需求部分确认 ｜ 提案版本：0.1

审批状态：approved（仅下列明确条款）｜ 交付状态：not_started

旧产品基线：无；参考输入为 PRD-001 v0.1 草案。本记录不将整份 PRD 标记为已批准。

## 用户原始决定

来源：本项目当前会话，用户在要求“帮我完善补充，通用的规则。”之后给出的四点回复：

> 1、K1和K1AI都要支持。目前我有一台K1 AI版的机器人。
> 2、首版功能边界：机器人控制+积木编程及工程兼容要求
> 3、交互与执行方式，控制页面应该是实时的，编程应该是上传后执行，以原生apk的方式实现为准
> 4、验收设备是K1 AI，能通过控制页面控制机器人，编程后，机器人能按照编程文件执行

## 确认范围

| 条款 | 需求 ID | 决定 |
|---|---|---|
| 设备范围 | REQ-DEV-001 | 支持 K1/K1AI，已有一台 K1AI 实机 |
| 首版方向 | REQ-SCOPE-001 | 控制、积木编程、工程兼容；具体兼容含义待明确 |
| 控制方式 | REQ-CTL-002 | 实时控制，参照原 APK 相关行为 |
| 编程执行 | REQ-VIS-002 | 上传文件后由机器人执行，参照原 APK 相关行为 |
| 实机验收 | REQ-ACC-001 | K1AI 实机完成控制页控制和程序文件执行 |

未批准或未明确部分：手机平台、完整动作/积木集合、工程兼容方向、手掰首版安排、技术选型、开发任务和完整测试用例。最新回复没有明确撤回原手掰需求，因此保留 REQ-MAN-001 待确认。

## 验收方向

在 K1AI 上完成 BLE 搜索和连接后，从控制页实时操作机器人；积木工程生成的动作文件上传并执行，实机表现与程序内容对应。详细输入、动作清单、程序样例、异常场景和量化指标待细化后形成正式测试用例。
