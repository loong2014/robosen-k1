# CR-005：原版蓝牙控制界面复刻

类型：需求变更｜审批状态：approved｜交付状态：implemented（代码 / 离线 / 构建）；实机验收 pending

提出日期：2026-10-08｜基线：PRD-001 v1.1、CR-003、CR-004｜提案版本：0.2

下方提案保留审批前的“拟新增 / 拟议”语态，范围已由末尾的用户批准记录正式生效；新增取证与实现进展另附，不重写批准历史。

关联：REQ-BLE-001、REQ-CTL-001/002、REQ-UX-001；拟新增 REQ-CTL-003/004/005、REQ-ACT-001/002。

## 原始诉求与范围

用户先要求“把app中缺失原始app的蓝牙控制，复刻到现在的蓝牙控制界面。”随后补充“复刻原版的动作中心的所有动作”。v0.2 保留 v0.1 的控制复刻范围，并把动作选择面板扩充为可独立浏览、播放的完整机器人动作中心。

参考 [蓝牙控制界面分析](../../analysis/reports/蓝牙控制界面分析.md) 和 [动作中心分析](../../analysis/reports/动作中心分析.md)，采用现有 Flutter 工程和 BLE 分层，适配 Android/iOS。

| 需求 | 已批准基线 / 当前代码 | 本提案具体行为 |
|---|---|---|
| REQ-CTL-001、REQ-CTL-002 | 四方向长按按钮、停止 | 改为可拖动的八方向摇杆，±0.5 方向阈值对应 0x01～0x08；松手 / 取消回中并发送停止；保留独立停止按钮。切页、后台、断线丢弃旧运动。已有保护优先于原版非零中心区细节 |
| REQ-CTL-003（新增） | 无动作快捷键 | 三个快捷动作，默认左拳 / 右拳 / 双拳；可从完整动作中心更换，恢复默认；绑定保存到独立版本化本地文件并重开恢复。默认 ProAction/ 路径与目录回传条目分开记录，不改写前缀、不计入已读目录总数。播放期间与摇杆 / 编程执行互斥；有进度、停止请求和断线未知状态 |
| REQ-ACT-001（新增） | 无动作中心 / 目录读取 | 从控制页进入动作中心，完整读取 Action/、Action/skill/、DownloadAction/ 的实际动作；按机器人动作 / 技巧 / 已下载分类，保留原名、目录和跨目录同名项。提供全部列表、分类计数、刷新及加载 / 空 / 部分失败状态；没有固定动作数或只显示三个拳击的限制 |
| REQ-ACT-002（新增） | 无目录动作播放 | 任意有效目录条目均可按完整路径 GB18030 + 0x17 请求播放，并显示选中项与进度、停止请求。与快捷键共用执行服务，不能不同入口同时启动。收到有效进度 100 才解除本次正常播放占用；写入完成、超时或停止请求不冒充实际完成。支持将任意目录条目绑定到三个快捷键 |
| REQ-CTL-004（新增） | 无音量调节 | 音量滑块与静音操作；回传同步不触发写入，修改后 500ms 合并发送最后值，0x0D 单字节。拟定本应用输入范围 0～100，属于待批准 UI 范围，不冒充原 APK Slider 资源取证；实机对照确认 |
| REQ-CTL-005（新增） | 仅显示电量原始值 | 控制页显示选定设备、业务连接状态、电量与音量反馈；提供控制设置 / 动作绑定入口、返回连接页。电量未标定前显示原始读数，不标为可靠百分比 |
| REQ-BLE-001 | 只接受 K1- / K1AI- | 与 K1 连接脚本一致接受 K1 / k1 前缀；连接仍检查 FFE0/FFE1 和业务握手。不纳入 GSEG- 连接页，不用名字直接认定型号 |
| REQ-UX-001 | 纵向四方向页面 | 改为清楚的状态区域、摇杆、三个快捷键、动作中心入口和控制设置；动作中心作为控制页内的子页面，保留已批准四页主流程。小屏 / 长名单可滚动，横竖屏可操作；缺原资源时不宣称像素一致 |

“所有动作”的拟议验收集合是原版机器人动作页从上述三目录读取的所有有效条目，包含已下载到机器人的动作；不要求为每个动作重写关节数据，也不假定某台机器人的名称适用于全部固件。名单和数量以实际读取及原版对照为准。

原版动作中心另有手机本地手掰 / 图形化工程，它们是用户工程、走编译上传流程；官方在线新动作下载则是独立联网页面。v0.2 不把这些来源冒充机器人内置动作：原编程任务按已批准范围继续，原 APK 工程导入、手掰编辑、云端新动作下载不随本提案新增。如用户所指“全部”还包含这些来源，需要调整此边界，不能在实施中悄悄放宽。

视频录制、固件升级、关机、动作删除 / 重命名和完整原应用设置页亦不随本提案新增。上述范围仍可由用户后续明确修改。

## 拟议验收

1. 八个方向与空载荷命令一一对应；中心区不发方向，释放 / 取消 / 切页 / 后台立即停止继续发送旧意图并在链路可用时尝试五次停止。多指、拖出边界及迟到写入不恢复旧运动。
2. 三项默认动作和完整路径正确；更换、确认 / 取消、恢复默认、应用重开可恢复绑定；损坏或未知配置不被静默覆盖。名称来自真实机器人目录，不能假装已读到。
3. 三目录完整结束后，新旧应用的有效完整路径集合一致；跨目录同名保留，刷新可看到目录新增 / 删除。空目录有真实结束依据；超时、解码失败、资源限制或只读到部分结果均不得标“全部已加载”。名单不硬编码固定数量。
4. 任意有效目录动作均有播放入口；逐项对照名称、路径、实际动作和完成表现。中文路径逐字节匹配可信 GB18030 向量；不擅自去扩展名。播放中禁用摇杆与编程启动；停止请求不误报物理停止；断线不自动恢复或重播，迟到通知不结束新请求，101 等异常进度不按完成处理。
5. 音量快速拖动只发最后值，回传同步不发设置；断线 / 切页取消待发送值，重连不补发。电量缺失显示未知，不能用补零冒充实测零电量。
6. K1 / k1 前缀候选可见，GSEG- 不成为支持设备；没有正确服务 / 握手仍不得 ready。
7. 两平台分别构建并用触摸屏覆盖页面操作；K1AI 记录全量目录与逐项动作、八方向、快捷动作、音量、停止及异常场景。未执行动作逐项列为 not_run；无实机不判机器人验收通过。
